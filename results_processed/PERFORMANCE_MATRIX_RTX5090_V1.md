# RTX 5090 严格构建性能矩阵（v1）

## 1. 可复现实验身份

- 运行编号：`20260824T010409Z_performance_full_rtx5090`
- GPU：NVIDIA GeForce RTX 5090（GPU 0，32,607 MiB，compute capability 12.0）
- 驱动：580.105.08
- CPU：2 × AMD EPYC 9654，OpenMP 128 线程
- CUDA 构建：严格 IEEE 路径，未启用 `--use_fast_math`
- 规模：每个域 13 个规模，最大 `N = 16,777,216`
- 方法：FP32、FP64、冻结自适应 v1、自适应但关闭梯度门控
- 计时：45 s 热预处理，10 次预热，30 次正式重复；分别记录纯核函数和 H2D + kernel + D2H 端到端时间
- 数据完整性：585 个计时组、17,550 条原始重复；每组恰好 30 条
- 区间估计：固定随机种子的 10,000 次配对 bootstrap，报告 95% 置信区间

本报告中的“持续交叉点”定义为：从该规模开始，当前规模以及其后所有更大规模的端到端加速比 95% 置信区间下界都大于 1。

## 3. 端到端持续交叉点

| 域 | 最小持续交叉规模 N |
|---|---:|
| BEM | 32,768 |
| Kepler | 8,192 |
| PV 单二极管 | 32,768 |

Peng–Robinson 是预先保留的负对照。它的 GPU 核函数在最大规模达到 1.79×，但 CPU 算法本身很轻，约 56.9 ms 的主机—设备往返开销使端到端加速比降至 0.20×。因此不能把纯 kernel 加速外推为应用级加速。

## 4. 精度—性能解释

- FP32 是性能上界而不是合格方案：它没有通过冻结正确性标准，不能用于论文的有效方法对比。
- 冻结自适应 v1 已在独立的、只运行一次的正式测试集上满足根误差和梯度误差门限，且五域均为零错误分支、零非有限结果。
- PV 与 Kepler 的修正率很高，因此自适应吞吐接近 FP64；CSTR 修正率低，同时分支安全，获得最大的有效端到端加速。
- 梯度门控在四个主域的最大规模开销不超过 0.14%，在 Peng–Robinson 为 2.55%。关闭门控并不是可接受的同精度优化：此前残差单门控审计中 Peng–Robinson 梯度相对误差 p99 达 5.37%，而冻结门控通过正式阈值。因此该消融证明的是可靠性代价，而不是一个可替换的更快方法。

## 5. 审计与边界

- 原始重复数据被完整保留，论文表格不得只引用汇总中位数而丢弃原始样本。
- 方法执行顺序按规模轮换，降低固定顺序造成的热状态偏差；配对 bootstrap 按重复编号配对。
- pinned host memory 的注册在计时区间之外；E2E 明确包含 H2D、kernel 和 D2H。
- 编译报告显示 FP32、FP64、自适应核分别使用 48、56、64 个寄存器；三者均为零寄存器 spill。
- 机器安装两块同型号 RTX 5090，本轮只使用 GPU 0；这不构成第二种 GPU 架构的外部验证。
- 本轮没有连续功耗轨迹，只有运行前后采样；不能据此声称能耗优势。
- 当前主矩阵仅覆盖严格构建。全局 fast-math 已在开发/校准集上因 CSTR 分支错误被拒绝；严格 FP64 的 Brent–Dekker/割线/Newton/Halley 算法矩阵已另行完成。df32、真实 OpenFAST 时序以及第二类 GPU 尚未完成。
