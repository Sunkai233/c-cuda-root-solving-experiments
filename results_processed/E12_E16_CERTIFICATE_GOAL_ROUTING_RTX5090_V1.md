## E12：认证准确性与紧致性

在全新冻结 test 上，FP32 仅残差门接受 25 个候选，其中 1 个是错误接受；条件门接受 73 个且错误接受为 0；完整后验根—分支—梯度门接受 64 个且错误接受为 0。df32 完整门接受 948/1000，错误接受为 0；其余保守拒绝升级到 FP64。

自动精度路径最终为 FP32 64、df32 884、FP64 52，1,000/1,000 未观察到根或分支失败。完整门并非“证明永不失败”：0/1000 的 Wilson 95% 失败率上界仍约 0.383%。

FP32 已接受样本的 `rho/实际根误差` 中位数约 1.008、p99 约 1.209；df32/FP64 的比值很大，主要因为分支见证加入固定 `5e-10 rad` 保护量，而多精度实际误差常接近机器零。这说明证书对 FP32 较紧、对高精度路径明显保守。

理论边界见 `docs/CERTIFICATE_GUIDED_ALGORITHM_V1.md`：CUDA 的 sampled Lipschitz majorant 经独立 test 审计，但不是 directed-rounding interval proof。

## E13：认证驱动精度选择

真实 600 s BEM 的 2,448,000 状态：

| 方法 | kernel ms | E2E ms | FP64/方法 E2E（95% CI） | FP32/df32/FP64 | 失败 |
|---|---:|---:|---:|---:|---:|
| FP64 compacted | 467.809 | 474.486 | 1 | 0 / 0 / 2,448,000 | 0 |
| 固定 df32 | 55.489 | 60.578 | 7.830 [7.816, 7.871] | 0 / 2,448,000 / 0 | **888** |
| 旧阈值 adaptive | 67.832 | 72.810 | 6.516 [6.402, 6.533] | 0 / 2,447,017 / 983 | 0 solver failure |
| 根+完整分支证书 | 203.986 | 209.120 | **2.268 [2.262, 2.271]** | 204,279 / 2,107,668 / 136,053 | 0 |
| 根+分支+梯度证书 | 240.713 | 245.657 | **1.931 [1.926, 1.934]** | 201,120 / 2,110,820 / 136,060 | 0 |

固定 df32 的高速度不合格。旧阈值 adaptive 很快，但不具备全量同区多根的分支见证；开发时关闭完整分支见证会让下游输出预算失闭合，因此它只能保留为经验门控基线。正式证书算法付出约 3 倍门控成本后，仍相对全 FP64 获得 1.93–2.27 倍 E2E 加速。

四个预算的两个实际输出误差均低于预测上界。目标导向调度显著改变精度资源分配，并在 1e-5 时把载荷误差从 uniform 的 1.638e-8 降至 2.998e-9，但慢约 5.3%；其他三个预算的时间差很小或 CI 接近 1。因此 E14 的正结论是“预算闭合和资源重分配”，不是普遍性能提升。

## E15：动态困难样本路由

正式 test 使用与校准不同的哈希排序种子 27183，困难比例为 0、0.001、0.01、0.05、0.1、0.25、0.5、0.75、1。比较 inline、warp-local、block-local、warp 聚合 global compaction 和冻结 auto 策略。

- `p=0.05` 时，虽然困难样本只有约 5.01%，`1-(1-p)^32=0.8063`；inline 为约 68 ms，而 global compaction 约 40 ms。
- `p=1` 时统一 inline 约 458 ms 最优或与其他方法等价；全局紧凑只增加开销。
- 不同 `p` 的实测最优在 block-local、global 和 inline 之间切换，证明“永远全局紧凑”不是最优策略。
- 冻结 auto 在 9 个点中 7 个选择了中位数最快的模式；相对逐点事后最优的最大 bootstrap regret 为 **0.128%**，中位 regret 约 0（轻微负值来自独立重复噪声）。45 个正式路由配置均 0 solver failure。

受控 E15 将实验生成器给出的困难比例 `p` 直接交给冻结 auto 策略，用来测量给定分类比例后的路由选择质量；生产运行所需的在线 `p` 估计、归约和决策开销未被单独计时。因此路由阈值只适用于当前 RTX 5090、2,448,000 状态和 robust BEM 路径，且结论条件于已知 `p`；E8 未执行，不能外推到第二类 GPU，也不能把本结果写成完整在线控制器的端到端性能。

## 结论边界

E12–E16 支持的核心贡献是：用经独立 test 审计的后验半径和目标分支见证选择逐样本精度；用输出敏感度检查全局物理量预算；用困难比例选择 GPU 路由。它不支持以下更强说法：

- sampled majorant 是严格区间算术证明；
- 目标导向调度在所有预算下都更快；
- 当前路由阈值可跨 GPU 架构迁移；
- 0/1000 等于数学上的零失败率。
