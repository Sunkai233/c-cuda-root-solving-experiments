# RTX 5090 真正 df32（二浮点数）次级候选实验（v1）

## 1. 结论与实验身份

本轮实现的是 `hi + lo` 两个 FP32 分量组成的 double-single（df32），不是把 FP64 结果截断成两个 float。加、减、乘、除使用显式 FP32 error-free transformation 与 FMA；`exp/log/sin/cos/sqrt` 也走 df32/FP32 软件路径。实际根求解内核的 SASS 中 `DADD/DMUL/DFMA/DSETP` 均为 0。

df32 在 RTX 5090 上不是普遍更快：BEM 明显受益，CSTR 仅在大规模下取得约 3.5% 的稳定收益；Kepler 与 Peng–Robinson 的端到端差异不显著，PV 因软件 `exp` 的串行代价而显著变慢。因此，“消费级 GPU 的 FP64 吞吐低”本身不足以推出 df32 必然加速。

本实验是冻结方案之后增加的次级候选。正式 test split 已由冻结自适应 v1 使用一次，本轮没有、也不得再次运行它。df32 正确性结果只来自 dev/cal，不能写成新的正式一次性 test 结论。

## 5. 机制解释

- BEM 的三角函数与长 FP64 算术路径使 RTX 5090 的低 FP64 吞吐成为主要瓶颈，df32 获得显著收益。
- CSTR 包含 256 点分支扫描和串行求根链，df32 只获得小幅收益；为避免 FP32 指数范围溢出，df32 与 FP64-equivalent 两边都使用相同的稳定 log-sigmoid 重写。
- Kepler 和 Peng–Robinson 的算术链较短，E2E 主要受传输与固定开销影响，df32 的 EFT 指令膨胀抵消了 FP64 吞吐优势。
- PV 的软件 df32 `exp` 多项式和范围缩放代价远高于 GPU 硬件/库 FP64 `exp` 路径，是明确的负结果。

## 6. SASS 审计

审计对象为实际性能二进制中的 `_Z11kernel_df32PK6DParamP7DOutputm`，而非单独构造的探针。截取 144,372 行 SASS：`DADD=0`、`DMUL=0`、`DFMA=0`、`DSETP=0`；作为交叉检查，`FADD=37,075`、`FMUL=3,013`、`FFMA=10,130`、`FSETP=5,411`、`MUFU=664`。`MUFU` 属于 FP32 特殊函数/倒数等路径，不是 FP64 指令。
